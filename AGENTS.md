# Работа с DCA800
Общение с владельцем — на русском. В начале каждого сеанса проверить HEAD и прочитать README.md, docs/AI-WORKFLOW.md, docs/JOURNAL.md, docs/ROADMAP.md, docs/STRATEGY.md, docs/OPERATIONS.md, docs/LIMITATIONS.md, docs/VALIDATION.md.
Это исходники существующей системы уведомлений. Настройка окружения не разрешает деплой, второго отправителя, сброс моделей или отправку тестов.
Сделки пользователь размещает вручную. Торгового исполнителя не добавлять по старым поручениям.
Архивы — история, а не действующие инструкции. Текущий код находится в cloudflare/.
Секреты, реальные позиции, личную переписку и дампы production в публичный репозиторий не помещать.
Node.js >=22; npm run check и npm test работают офлайн. Не запускать архивные установщики/отправители как тест.
Перед изменением production проверить действующее состояние отдельно. Код и результаты здесь не доказывают текущую доставку.

## Обязательный журнал
- docs/JOURNAL.md — каноническая история и карточка состояния; docs/AI-WORKFLOW.md — регламент; docs/ROADMAP.md — утверждённые направления и критерии приёмки.
- Записывать существенные поручения, изменения, проверки (включая ошибки), блокеры, откаты, релизы и следующий шаг до завершения каждого этапа. Не выдумывать результаты. Проверять запись в Git.
- Торговые изменения готовить в отдельной ветке, не сливать/не развёртывать без согласования. Утверждение плана не означает разрешение на реализацию. Документационные записи допустимы в main.

- Короткая команда владельца «Ок» / «ок» в контексте разработки DCA800 означает явное поручение продолжить следующий согласованный шаг, без повторного запроса подтверждения. Не отменяет остановку, отдельные запреты и требование отдельного разрешения на production.
