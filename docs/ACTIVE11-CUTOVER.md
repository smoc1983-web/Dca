Новая сводка имеет суффикс `:ACTIVE11`. Прежняя запись за тот же день блокирует выпуск второй сводки. Старые сводки остаются в очереди для сверки. Диагностика с `activeOnly: true` отдельно показывает удержанные уведомления, замороженные модели и отсутствующие активные ключи.

Перед откатом на старый код сверить обе версии дневного ID и удержанные записи. Старый отправитель может выпустить вторую сводку за тот же день или доставить удержанные записи. 1. После остановки расписания и завершения выполняющихся задач запустить [проверку очереди](../scripts/active11-rollback-readiness.sql) с датой Астрахани. Запрос возвращает только причины остановки и количество записей.

3. Для отката использовать сохранённую версию Worker с текущей D1. Сверить совместимость модели, конфигурации, расписания и привязок. Снимок D1 использовать отдельно при повреждении данных с учётом уже доставленных сообщений.
