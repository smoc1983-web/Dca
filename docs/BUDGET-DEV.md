# 03 / 03.1 — тестовый бюджет, первый инкремент
Изолированный модуль portfolio-budget.mjs. Не подключён к Worker, реальным сделкам или балансам. Политика equal-slots-v1 — явная тестовая гипотеза, не настройка production. Входы capital, freeCash (предоставленный пул до внутренних резервов, НЕ автоматически balance.available биржи), maxCycles, feeRate обязательны. Бюджет цикла = выделенный капитал / maxCycles, вниз до 8 дробных знаков USDT. START = 25/800 бюджета, следующие 5 сумм ×1.5; номиналы вниз, комиссии вверх до 8 знаков. Номинальный предел 70%, полный резерв с комиссиями должен помещаться в бюджет и общий доступный пул. Учитываются входные комиссии, не комиссии выхода. Реальные фильтры и фактические исполнения не подменяются расчётными.
Резервы пока только ДО исполнений: неизменяемый снимок плана и версии настроек, отказ при недостатке полного резерва, повторном символе или лимите циклов; при смене капитала/лимита прежние планы сохраняются и дефицит виден, новые входы блокируются. Освобождение только неисполненного резерва. Переходы чистые, revision проверяется, данные JSON-совместимы; это ещё не атомарная БД и не защита нескольких независимых писателей без CAS.
Далее: персистентный журнал операций с атомарной проверкой ревизии, подтверждённые исполнения/частичные исполнения, резерв оставшихся DCA, освобождение после закрытия, разделение денежных потоков и PnL, сверка с журналом и фильтрами. Предлагаемые параметры не активированы; плечо отдельно. 

## Ручные исполнения, отдельный расчёт (требование владельца 26.11.2026)
- Сигнал модели — только рекомендация; реальные покупки/продажи пользователь выполняет вручную. manual-cycle.mjs строит сводку по подтверждённым исполнениям из журнала, привязанным к id резерва, фактическим цене/количеству/комиссии; модельные события игнорируются. Сравнение с ценой сигнала только справочное. Фактические превышения бюджета отображаются, не отбрасываются; новые рекомендации блокируются при отклонении.
- Проектное правило для нескольких частичных исполнений: после явного завершения ступени использовать её средневзвешенную фактическую цену как якорь следующего DCA; округление покупки вниз по tick. TP от фактической средней цены +3%, округление вверх, отдельно оценка чистого PnL с комиссией выхода. Не обещание чистых 3%. Не менять исходные 19 моделей, не открывать/закрывать ордера.
- Пока чистая проекция, не транзакционное изменение резерва: остаток по незавершённым ступеням, стоимость позиции, отклонения и предупреждение после закрытия о необходимости отменить оставшиеся ордера. Не освобождать резерв автоматически. При неоднозначном DCA/перерасходе требуется сверка. Далее CAS-хранилище, атомарная привязка исполнений/подтверждений, безопасное освобождение и UI ручного подтверждения. Реальные цены/балансы не запрашивались.

## Постоянное хранилище предварительного бюджета и ручных исполнений
- budget-store-schema.sql и budget-store.mjs: append-only журнал команд, revision и CAS одновременно по ревизиям бюджета/журнала сделок. Один INSERT и SQL-триггер фиксируют подтверждённое ручное исполнение и новый снимок бюджета атомарно. Дубли команд/исполнений проверяются, несовпадения отклоняются. Сигнал не создаёт исполнения.
- Консервативный hold = max(исходный полный резерв, суммарная себестоимость покупок + оставшийся резерв). Частичная продажа не освобождает деньги автоматически. Перерасход, неизвестные ручные исполнения и изменение истории освобождённого цикла блокируют новые резервы. Закрытие по подтверждённой продаже и явная отмена оставшихся ордеров обязательны; для освобождения исполненного цикла требуется новый сверенный freeCash (пул до внутренних резервов, не биржевой свободный баланс). PnL не капитализируется автоматически. Это проектное правило тестового контура, не утверждённая политика production.
- Пока нет полноценной сверки денежных потоков/биржевого баланса, авторизации, коррекции исполнений после освобождения, импортов вне резервов с процедурой восстановления, тестов D1/миграции. Чтение сводки состоит из нескольких запросов; запись защищена CAS, сводка не гарантирует атомарный снимок при конкуренции. Только SQLite. 7 новых тестов, CI проверяется отдельно.

## Сверка денежных потоков (отдельный тестовый контур)
- cash-reconcile.mjs: начальный подтверждённый USDT-остаток без открытых позиций, подтверждённые вводы/выводы, фактические ручные исполнения, комиссии USDT отдельно от эквивалента других валют. Реализованный PnL берётся из журнала и не включает вводы/выводы. Сверка с предоставленным снимком free+locked, проверка возраста/изменения истории/расхождения. Консервативный доступный остаток ограничен free минус весь оставшийся внутренний резерв и свободным лимитом бюджета; блокировки биржи могут быть уже учтены в резерве, поэтому результат намеренно консервативен. Это не equity и не общая оценка всех активов.
- cash-store-schema.sql/cash-store.mjs: append-only команды подтверждённого открытия учёта, денежных потоков, наблюдаемого баланса, CAS по журналу денежных потоков и исполнений. Новый поток инвалидирует наблюдение; новая ревизия журнала (включая модельную, консервативно) требует новой сверки. Сводка проверяет три ревизии после чтения. Не изменяет бюджет автоматически, не авторизует резерв, не капитализирует PnL. Только синтетические USDT-данные, не проверка реального биржевого счёта. Начало с открытыми позициями, комиссии/переводы других активов, корректировка денежных потоков, интерфейс подтверждения, интеграция gate в резервирование и реальный D1 остаются открытыми.
- 8 новых тестов: ввод/вывод и PnL, комиссии, дубли/частичные продажи, устаревший/отсутствующий/неверный снимок, locked/резерв, постоянство/дубли, инвалидирование наблюдения, конкурентные команды.
