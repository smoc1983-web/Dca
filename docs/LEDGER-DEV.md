# Development foundation / trade ledger

Branch dev/dca800-foundation. No imports into worker.mjs, no production configuration, no secrets or delivery. CI runs original core tests, syntax/watchlist and all offline tests; no market or Telegram requests by the tests. 
The first ledger increment is an offline replay/calculation library for long-only USDT spot fills. Separate model/manual sources; manual fills require confirmation. Cycle ID and execution ID are supplied by caller, unique per source. Append order is preserved, per-cycle timestamps must not go backward. Exact duplicates are ignored, conflicting IDs rejected. A third-currency fee needs an explicit historical conversion rate; no estimate if missing. Base fees reduce inventory, quote/converted third-asset fees affect cost/proceeds. Average entry excludes quote/third fees but accounts for net received quantity; average cost includes entry fees. Realized % denominator is released cost basis. Mark-to-market optionally subtracts estimated exit commission. Uses binary floating point with explicit tolerance for closing quantity; fixed-point/exchange precision validation remains necessary before real accounting. 
No persistence/API/CSV/corrections yet; no live integration, no automatic order execution. Next: isolated SQLite/D1-compatible schema, event persistence with idempotency and transactional correction/audit, model event adapter, integration tests. CI result must be checked, not assumed.
