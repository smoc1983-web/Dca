# Development foundation / trade ledger

Branch dev/dca800-foundation. No imports into worker.mjs, no production configuration, no secrets or delivery. CI runs original core tests, syntax/watchlist and all offline tests; no market or Telegram requests by the tests. 
The first ledger increment is an offline replay/calculation library for long-only USDT spot fills. Separate model/manual sources; manual fills require confirmation. Cycle ID and execution ID are supplied by caller, unique per source. Append order is preserved, per-cycle timestamps must not go backward. Exact duplicates are ignored, conflicting IDs rejected. A third-currency fee needs an explicit historical conversion rate; no estimate if missing. Base fees reduce inventory, quote/converted third-asset fees affect cost/proceeds. Average entry excludes quote/third fees but accounts for net received quantity; average cost includes entry fees. Realized % denominator is released cost basis. Mark-to-market optionally subtracts estimated exit commission. Uses binary floating point with explicit tolerance for closing quantity; fixed-point/exchange precision validation remains necessary before real accounting. 
No persistence/API/CSV/corrections yet; no live integration, no automatic order execution. Next: isolated SQLite/D1-compatible schema, event persistence with idempotency and transactional correction/audit, model event adapter, integration tests. CI result must be checked, not assumed.

## Второй инкремент: изолированное постоянное хранилище
- cloudflare/trade-ledger-schema.sql: отдельная append-only таблица с уникальным op_id; запрет UPDATE/DELETE триггерами. Не применять к production.
- cloudflare/trade-store.mjs: D1-образный интерфейс prepare/bind/all/run, snapshot/audit/write; хранит исходные и исправленные ручные исполнения, автора, причину, время и версию. Одно атомарное условное INSERT проверяет ревизию журнала; конкурирующая запись повторно проверяет данные. Повтор исходного импорта после исправления не откатывает его. Исправление только ручных исполнений, без смены идентичности/стороны; удаление/отмена отдельным будущим этапом.
- tests/trade-store.test.mjs: локальная SQLite через node:sqlite (Node 22), временный файл с закрытием/открытием, дубли, аудит, недопустимые исправления, конкуренция и защита записей. Данных production нет. Это не проверка настоящего Cloudflare D1 и не гарантия его совместимости.
- Ограничения: полный replay истории при записи (не для масштабного production без оптимизации), подтверждение/авторизация должны выполняться внешним доверенным интерфейсом; нет адаптера событий движка, CSV, точной decimal-арифметики, развёртывания. Следующий шаг: проверить CI, затем адаптер модельных событий и тесты сверки с движком.

## Третий инкремент: адаптер модели и CSV
- model-ledger.mjs: вычисляет шаг на копии состояния, сопоставляет реальное модельное исполнение (с учётом округления, комиссии, проскальзывания) с изменением cash/qty. Идентификатор экземпляра модели обязателен, цикл привязан к START; неизвестная история блокируется, не создаётся вымышленный вход. Запись до возврата нового cursor; повтор идентичного шага идемпотентен. Не является атомарной интеграцией cursor/outbox/ledger в D1, допускается только в изолированном контуре. Не менять параметры в середине повтора.
- ledger-csv.mjs: экспорт текущих исполнений и итогов циклов с явным выбором model/manual, CSV quoting и защита текстовых формул; без автоматической публикации/отправки. Авторизация внешняя. Отрицательные числа остаются числовыми.
- tests/model-ledger.test.mjs: полный цикл TP и STOP, сверка баланса и позиции после усреднений, replay, отказ хранилища, отсутствие START и CSV. Проверки на синтетических свечах, не исторический бэктест. Decimal/биржевая точность, отмена, D1 и атомарное сохранение cursor/outbox остаются отдельными задачами.

## Четвёртый инкремент: точность денежных расчётов
- ledger-decimal.mjs: BigInt с 24 дробными знаками, округление половины от нуля, предел абсолютной величины <10^24. Входы пока JS Number, перевод через их десятичное представление; это не восстановление точности уже округлённых биржевых данных. Модельный движок не меняется.
- trade-ledger.mjs: расчёт количества, комиссий, себестоимости и PnL в целых единицах; частичные выходы распределяют себестоимость с контролируемым округлением, финальный закрывает остаток. В отчёте exact содержит строки основных денежных итогов; прежние числовые поля сохранены для совместимости. Только модельный источник сохраняет прежний допуск закрытия из-за float исходного движка; ручное превышение количества отклоняется.
- 5 новых тестов: десятичное умножение, границы, точное закрытие, сохранение базы частичных выходов, превышение количества и нереализованный PnL. До production остаются точные строковые биржевые входы, фильтры инструмента, проверка экспорта exact и атомарность cursor/outbox/ledger, реальный D1.

## Пятый инкремент: атомарная фиксация модельного шага
- atomic-model-schema.sql / atomic-model-store.mjs: отдельные таблицы dev_model_registry, dev_model_steps, dev_model_outbox. Не миграция production. Состояние — последний неизменяемый шаг; конфигурация экземпляра фиксирована. SQL INSERT с проверкой ревизий модели и журнала плюс триггер записи исполнения и тестового события очереди. При SQL-ошибке откат всей операции. Повтор идентичной свечи идемпотентен, конфликт исторических данных/пропуск отклоняется. Не отправляет сообщений.
- 6 тестов: полный цикл, искусственный отказ outbox, перезапуск файловой SQLite, конкурентный дубль, неизменность конфигурации и проверка свечей, шаг без сигнала. D1-триггеры, производительность (полная история), интеграция с существующими моделями/alerts и миграция ещё не проверены. Точный строковый ввод/биржевые фильтры остаются следующей задачей.

## Шестой инкремент: строковая точность и фильтры
- ledger-decimal принимает строгие десятичные строки без экспоненты, до 24 значащих дробных знаков, не теряя точность через Number. В trade-ledger/store каноническое представление сохраняет число только при точном обратном преобразовании, иначе строку; exact содержит исходные финансовые поля и итоги. CSV дополнен exact-колонками; импорт в Excel с длинными числами требует текстового формата (Excel ограничивает числовую точность). Старые числовые колонки сохранены.
- order-filters: чистая проверка заранее переданных PRICE_FILTER/LOT_SIZE/NOTIONAL границ для LIMIT и округление плановой покупки вниз по tick/step без превышения номинального бюджета. Не учитывает комиссии, динамические percent-price фильтры, market orders, доступный баланс, актуальность фильтров; не применяет новые правила к прошлым исполнениям и не размещает ордера. Значения в тестах синтетические; реальные фильтры нужно получать и проверять отдельно.
- 6 новых тестов на строковую точность, PnL и конвертацию, дубли, округление/минимумы, SQLite/CSV. CI проверяется отдельно. D1/production не подключены.
