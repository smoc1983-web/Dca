# Допуск альтернативного источника Binance Spot (исследование)
28.11.2026. Ошибки реального Worker 403/451 подтверждены владельцем. Не обходить ограничения источника, не подменять временем системы и не смешивать свечи разных бирж.

## Кандидаты
- Официальный Binance market data: https://developers.binance.com/en/docs/products/spot/rest-api и https://developers.binance.me/en/docs/products/spot/faqs/market_data_only. Уже используемый REST возвращает 403/451. Официальный WebSocket указан в документации, но доступ и право использования не подтверждены; не подключать как обход запрета.
- Binance public daily archives https://github.com/binance/binance-public-data — эталон закрытой истории с CHECKSUM, не источник сигналов в реальном времени. Spot timestamps с 2025 в микросекундах; нормализовать строго.
- CoinAPI https://www.coinapi.io/products/market-data-api/exchanges/binance и https://www.coinapi.io/products/market-data-api/docs/rest-api/ohlcv/ohlcv/symbol_id/history/get — кандидат отдельного поставщика Binance SPOT OHLCV, требуются подтверждённое право доступа, тариф/лимиты и реальная проверка всех 19 пар. Документация не доказывает точность OHLC, доступность или достаточную свежесть. Не покупать тариф и не запрашивать ключ в чате. Другие биржи не эквивалентны Binance.

## Проверка перед допуском
1. Внешний оператор проверяет законность/условия использования и доступность поставщика из согласованного окружения.
2. Выгрузить семь завершённых суток UTC всех 19 пар (11 active + 8 legacy) и независимо сверенный официальный spot archive. Никаких открытых свечей, пропусков, интерполяций. 2016 5m bars на пару, 38304 всего. Формат обеих нормализованных выгрузок: {venue:"BINANCE",market:"SPOT",interval:"5m",start,end,series:[{symbol,rows:[{time,closeTime,open,high,low,close}]}]}. Время ms, end exclusive. Для provider period_end exclusive closeTime=end-1 только после проверки семантики. Не использовать time_close последней сделки как границу свечи.
3. node scripts/check-spot-source-parity.mjs reference.json candidate.json report.json. Нулевое количество расхождений OHLC и границ — необходимое, не достаточное условие. SHA256 нормализованных рядов, первая ошибка. Проверка не подтверждает происхождение самообъявленных входов, их лицензирование, свежесть или volume; текущий движок использует только OHLC. Дополнительно сверить native TF (включая 45m из 15m), последовательность сигналов и состояние на отдельном стенде.
4. Проверить задержку закрытых свечей, независимый exchange clock / доверенный механизм подтверждения закрытия, отсутствие пропусков, лимиты/429/403/451, восстановление по непрерывному cursor. Любая неопределённость — fail closed. Не использовать старые данные для нового входа. Не менять рабочую D1.
5. Только после отдельного согласования сверить deployed bundle, провести shadow/стенд без второго отправителя, согласовать rollback и переключение. Данный offline gate всегда возвращает productionAllowed=false.

Сетевой тест нового поставщика не выполнялся. Реального кандидата пока нет; синтетические тесты лишь проверяют контроль качества.

## План бесплатной сверки (28.11.2026, draft)
CryptoDataAPI Hobbyist: 1000/day и 10/min после email verification, 100/day до неё. https://cryptodataapi.com/pricing ; https://cryptodataapi.com/blog/crypto-market-data-api-trading-agent ; https://cryptodataapi.com/blog/fetch-1h-ohlcv-candles-btcusdt-api . Тариф позиционируется для разработки и прототипирования; право постоянного использования в рабочем боте не установлено. Не подключать без проверки условий и квоты ключа. Бесплатный trailing-window klines до 1000 баров на одну пару по документации; фактическое покрытие/свежесть/точность не проверены.
- 11 enabled каждые 30 минут = 528/day; 8 excluded/legacy каждые 60 минут = 192/day; 720 scheduled, 230 extra, 50 unallocated safety margin. Локальный потолок 950 attempts rolling 24h и 8 rolling 60s. Слоты UTC с разнесением, максимум 1 planned request/minute, не догонять пропущенные слоты всплеском. Все попытки включая HTTP failures должны резервироваться до отправки; проверка фактического Retry-After и прекращение на запрете. Не использовать второй ключ для обхода квоты.
- scripts/spot-crosscheck-plan.mjs: pure offline schedule/quota decision, не сохраняет attempts, не вызывает API. Для конкурентной/перезапускаемой работы нужен отдельный atomic persistent ledger, actual provider quota, retry policy, согласованная привязка источника. Нельзя считать pure decision атомарным разрешением.
- Сверка одинаковых закрытых OHLC и границ времени на одинаковом TF (45m из 15m), несколько баров на запрос. Не сравнивать Spot с Futures. Нужен независимый reference (первичные свечи в текущем Worker не сохраняются отдельным рядом; потребуется dev cache или согласованный read). Если Binance недоступен, пометить unverified, а не подтверждать совпадение по одному источнику. Сверка не открывает сделки, не заменяет exchange clock и не лечит 451. Автоматический fallback/production не разрешён.
