# MT4/MT5, CScalp, TigerTrade и Vataga применительно к DCA800

Проверено по официальной документации 1 ноября 2026 года. Это исследование возможностей и проект следующего этапа. Новые прогоны стратегии внутри перечисленных платформ не выполнялись, терминалы не устанавливались, работающие сигналы не изменялись. Под TigerTrade здесь понимается Tiger.com Windows, а не Tiger Brokers OpenAPI.

## Выбор для нашей задачи

Для текущего режима «сигнал в Telegram → ручная сделка на Binance Spot» сохранять независимый расчёт DCA800 и рассматривать **TigerTrade Windows как основной терминал исполнения**, **CScalp как более простой вариант ручного исполнения**, **Vataga как альтернативу для рабочего пространства и контроля сделок**. Если нужен отдельный специализированный стенд тестирования с интерфейсом и оптимизатором — **MT5**. Перенос в MT4 возможен, но для новой реализации я предпочёл бы MT5.

Это инженерный выбор по подтверждённым функциям, а не результат сравнительного испытания терминалов на этом компьютере.

| Платформа | Встраивание логики | История и таймфреймы | Telegram | Роль для DCA800 |
|---|---|---|---|---|
| MT5 | Переписать в MQL5-советник. Возможен режим только сигналов | Полноценный Strategy Tester и оптимизация; 21 стандартный период, включая M15/H1 | Написать вызов Bot API через WebRequest в советнике | Отдельный стенд исследования и возможная реализация сигнального робота |
| MT4 | Переписать в MQL4-советник | Тестер и оптимизация; M15/H1 доступны, стандартная сетка периодов уже, чем MT5 | Через WebRequest из советника | Имеет смысл при существующей инфраструктуре MT4 |
| CScalp | Штатный запуск нашего кода не подтверждён; официальный FAQ указывает ручную торговлю | Автоматический тестер пользовательского алгоритма с перебором параметров не подтверждён | Сохранить нашего внешнего бота; CScalpbot — отдельный продукт | Быстрый ручной ввод объёма, работа со стаканом и ордерами |
| TigerTrade Windows | Пользовательский индикатор на C# с моделью DCA и сигналами технически реализуем | Симулятор на живом рынке и Плеер для исторического воспроизведения; пакетный оптимизатор DCA не подтверждён | Штатные уведомления индикаторов и исполнений в настраиваемого бота | Наиболее подходящий из изученных вариантов для совмещения ручной торговли, визуальных сигналов и Telegram |
| Vataga Crypto / Vataga.terminal | Публичный SDK пользовательских стратегий и прямой импорт нашего Pine не подтверждены | Графики разных периодов есть; автоматический тестер нашего алгоритма и оптимизатор не подтверждены | Есть пересылка командных алертов в Telegram; произвольная автоматическая DCA-логика через неё не подтверждена | Ручное исполнение, объёмы в USDT, авто-SL/TP и журнал |

Отсутствие найденного публичного подтверждения не означает невозможность закрытого API или будущего расширения. Возможность торговли через API биржи также не означает наличие API для программирования самого терминала.

## MT5 и MT4

У MT5 есть многопоточный тестер советников, мультивалютные тесты, настройка периода и моделирования исполнения. MT4 тоже поддерживает исторические тесты и оптимизацию роботов. Исходный Pine или наш JavaScript напрямую не загружается: нужен перенос логики с проверкой соответствия сигналов. [Тестер MT5](https://www.metatrader5.com/en/terminal/help/algotrading/testing), [тестер MT4](https://www.metatrader4.com/en/automated-trading/strategy-tester).

Для нашей пары важно сохранить **Binance UNIUSDT Spot**, а не заменить её другим брокерским инструментом с похожим названием. В MT5 можно создать пользовательский символ и импортировать минутные бары или тики. Минутная история служит основой старших периодов. Такой символ подходит для тестирования, но сам по себе не даёт реального исполнения на Binance. Для живого получения Binance-данных потребуется отдельный адаптер, если подходящий поток не предоставляет подключение. Пользовательские символы нельзя оптимизировать через MQL5 Cloud Network; доступны другие агенты, включая локальные. [Пользовательские инструменты MT5](https://www.metatrader5.com/en/terminal/help/trading_advanced/custom_instruments).

M15 и H1 стандартны в обеих платформах. MT5 также имеет M2/M3/M10/H2/H3 и другие периоды. **M45 не входит в стандартные 21 период MT5**: для нашего кандидата 45 минут понадобится агрегация данных в коде или отдельное представление. Нельзя обещать прямой запуск всех ранее проверенных 24 периодов без доработки. [Периоды MQL5](https://www.mql5.com/en/book/applications/timeseries/timeseries_symbol_period), [периоды MQL4](https://docs.mql4.com/constants/chartconstants/enum_timeframes).

Telegram подключается из советника через HTTP Bot API. В MT4/MT5 WebRequest недоступен в Strategy Tester и не предназначен для вызова из индикатора. Поэтому бэктест должен писать события в журнал/файл, а отправка живых сообщений проверяется отдельно. Для HTTP требуется разрешённый адрес назначения в настройках платформы. [WebRequest MQL5](https://www.mql5.com/en/docs/network/webrequest), [WebRequest MQL4](https://docs.mql4.com/common/webrequest).

## TigerTrade Windows

Подтверждены собственные индикаторы на C# и штатная отправка их уведомлений в Telegram. Можно разработать индикатор DCA800, который ведёт модель START/DCA/TP/STOP и рисует среднюю, сумму следующей покупки и TP. Возможность конкретного формата сообщения, расчёт на закрытой свече, восстановление состояния и отсутствие повторов нужно проверить в прототипе SDK. Поддержка индикаторов не равна готовому движку произвольной автоторговли. [Пользовательские индикаторы](https://support.tiger.com/english/frequently-asked-questions/questions-about-indicators), [Telegram](https://support.tiger.com/english/settings/terminal/telegram-alerts).

Режим Симулятор предназначен для торговли на демо-счетах по живым данным, Плеер — для воспроизведения истории. Это полезно для репетиции ручных DCA и оценки реакции на сигналы, но не заменяет автоматически таблицу результатов тысяч комбинаций параметров. Плеер имеет отдельные лицензионные ограничения и не входит в бесплатную криптолицензию согласно документации. [Режимы торговли](https://support.tiger.com/nastroiki/rezhimy-torgovli).

Документированный Tiger API — локальный WebSocket-сервер. Команда `setLinkSymbol` переключает инструмент в группе окон. Его можно использовать как помощник: сигнал нашего процесса открывает нужный тикер для ручной проверки. Документированных команд произвольной отправки торговых ордеров на этой странице нет. [Tiger API](https://support.tiger.com/english/development-for-tiger.trade-windows/tiger-api).

Практически полезен **Dynamic SL/TP**: защитные уровни можно привязать к средневзвешенной цене позиции. Нужно проверить после усреднения обновление цены и количества TP и размещение заявок именно на стороне биржи, если требуется независимость от включённого терминала. Трейлинг в документации описан как локальный. [Защитные стратегии](https://support.tiger.com/english/settings/basic-setup/setting-up-defensive-strategies).

Серверные ценовые алерты Tiger работают при закрытом терминале, но это отдельная функция сигнальных уровней. Она не подтверждает серверное выполнение нашего пользовательского C#-индикатора с RSI и пятью усреднениями. [Серверные алерты](https://support.tiger.com/tablicy/servernye-alerty).

## CScalp

Официальный FAQ прямо описывает терминал как инструмент ручной торговли без автоматической торговли. Поэтому предлагаемый маршрут — наш независимый расчёт → наш Telegram → ручное исполнение в CScalp. Заранее выставленная лестница лимитных покупок будет иной стратегией: исходная DCA800 ждёт закрытия свечи и допускает одну команду за бар. [FAQ разработчика](https://fsr-develop.com/frequently-asked-questions-cscalp-faq).

У разработчика есть CScalpbot с собственными отчётами и алертами. Это не подтверждает импорт пользовательской DCA-логики или отправку из терминала в уже используемого нами бота. [CScalpbot](https://fsr-develop.com/official-bot-cscalp-in-telegram).

## Vataga

Подтверждены подключения к криптобиржам, работа с Binance Spot, объёмы в USDT и автоматическое выставление SL/TP в процентах или USDT. Для нашей схемы полезны контроль реальной позиции и объёмов. Документация описывает процентный TP от цены входа; точный пересчёт от общей средней после каждого усреднения нужно проверить отдельно. [Возможности терминала](https://vataga-trading.github.io/docs/ru/terminal/intro-terminal), [настройки торговли](https://vataga-trading.github.io/docs/ru/terminal/terminal-main-settings/trading-settings).

С 22 октября 2026 года есть дублирование **командных** алертов в Telegram-канал или группу через привязку команды. Это подтверждённая интеграция, но она не подтверждает самостоятельный расчёт нашей стратегии, публичный входящий API для её событий или использование произвольного токена существующего личного бота. До такой проверки сохранять наш прямой канал уведомлений. [Официальный релиз](https://vataga.trading/ru/news/releases/alerty-komandy-v-telegram-novaia-vozmozhnost-vataga-crypto).

Наличие графиков TradingView в стороннем терминале не означает наличие Pine Editor и Strategy Tester. Встраиваемые библиотеки TradingView сами по себе не поддерживают Pine Script и тестер. Прямую загрузку нашего Pine в Vataga официально подтвердить не удалось. [Ограничения библиотек TradingView](https://www.tradingview.com/charting-library-docs/latest/resources/Frequently-Asked-Questions/).

## Что улучшать в нашей стратегии

Следующие пункты — предложения к разработке и проверке, а не уже доказанное увеличение прибыли.

1. **Общий капитал двух таймфреймов.** При стартовом ордере 25 USDT и множителе 1,5 весь цикл стоит 519,53125 USDT: 25 + 37,5 + 56,25 + 84,375 + 126,5625 + 189,84375. Это 64,94% от 800; ограничение 70% в таком полном цикле ещё не достигается. Два независимых цикла требуют 1 039,0625 USDT. Если реальный депозит один и равен 800, нужен общий лимит капитала и правило приоритета сигналов. Нельзя трактовать две модели по 800 как один счёт на 800.
2. **Реальные исполнения.** Сейчас модель не знает, что и по какой цене куплено вручную. Добавить подтверждение покупок/продаж и распределение их по циклам. На одном спотовом счёте одна монета общая, а виртуальные циклы M15/H1 могут иметь разные средние: продажа всей биржевой позиции по сигналу одного цикла затронет второй. Нужен учёт принадлежащего циклу количества либо отдельное ведение капиталов.
3. **TP и исполнение.** Сравнить исходный выход по закрытию свечи выше средней ×1,03 с постоянно стоящим биржевым лимитным TP. Второй вариант может сработать внутри свечи и изменит результаты. После каждой фактической покупки пересчитывать TP от реальной средней, учитывать комиссии и остаток количества. Восстанавливать модель после раннего ручного TP.
4. **Проверяемые варианты риска.** Сравнить фиксированные DCA-шаги с шагами по ATR и фильтр старшего таймфрейма, применяемый к новым циклам. Отдельно проверять разрешение/запрет усреднений в падающем режиме. Показатели — просадка, прибыль относительно просадки и время блокировки капитала, а не только чистая прибыль. Ранее экспериментальная защита 12% ухудшила результаты — повторно обещать её преимущество оснований нет.
5. **Реальное время уведомлений.** Моделировать исполнение после доставки сигнала и ручной реакции, а не гарантированно по уже прошедшей цене закрытия. Проверять частичные исполнения, отказ заявки, минимальный объём, комиссию и перезапуск. Кластерные/стаканные фильтры требуют собственной соответствующей истории; свечного CSV для их честного теста недостаточно.

## Предлагаемая программа проверки

Сначала сохранить неизменный эталон v14 и сделать исследовательскую копию. Использовать одинаковую историю Binance Spot и одинаковые даты для всех периодов: 3, 5, 15, 30, 45 минут; 1, 2, 3, 4 часа. Проверку M45 проводить там, где есть корректная агрегация. Быстрые интервалы не сравнивать по короткой истории с длинными интервалами за несколько лет.

Проводить две отдельные серии: эталонное моделирование условий Pine и моделирование фактического ручного исполнения. Тестировать M15 и H1 как отдельно, так и совместно при одном капитале 800. Начальное состояние открытого цикла и прогрев RSI/EMA должны совпадать. Открытые позиции в конце периода учитывать одинаково.

Сначала проверять совпадение событий START/DCA/TP/STOP между реализациями, затем финансовый результат. Каждое изменение проверять отдельно. Для выбора параметров использовать один участок истории, для оценки — следующий, ещё не использованный при подборе; затем переходить к следующей паре участков. Уже просмотренные периоды 2025–2026 не считать полностью слепым тестом.

В итоговую таблицу включать чистую прибыль, максимальную просадку, число полных циклов, худший цикл, максимальный занятый капитал, время удержания, комиссии, долю незакрытых циклов и чувствительность к задержке исполнения.

В предыдущем сравнительном прогоне TradingView за 01.02.2025–01.11.2026 исходная логика показала: H1 +26,66% при просадке 28,70%; M45 +25,08% при 15,99%. Это аргумент дополнительно исследовать M45 и общий риск, а не доказательство будущего преимущества. Эти цифры не являются результатами MT5, TigerTrade, CScalp или Vataga.

Практический следующий шаг — тестер на уже перенесённом движке с общим лимитом капитала M15/H1 и сравнением двух моделей TP; затем прототип визуального DCA-индикатора в TigerTrade или независимая проверка в MT5. Доказанного нового прироста прибыльности на этом этапе нет.
